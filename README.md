# پیش‌بینی مصرف گاز بر اساس داده‌های هواشناسی (Gas Consumption Forecasting)

این پروژه با استفاده از داده‌های تاریخی هواشناسی (دمای بیشینه/کمینه/میانگین و بارش) به پیش‌بینی مصرف ماهانه گاز در دو حوزه (منطقه) می‌پردازد. دو رویکرد مدل‌سازی مختلف پیاده‌سازی شده: مدل‌های یادگیری عمیق مبتنی بر LSTM و مدل آماری سری زمانی SARIMA.

## ساختار پروژه

```
.
├── weather.py                  # ساخت ستون تاریخ میلادی و معادل شمسی از سال/ماه
├── match_dates.py               # ادغام ستون‌های تکه‌ تکه‌ شده اکسل هواشناسی (خروجی: result_stacked.xlsx)
├── main_project.py              # مدل پایه: LSTM تک‌لایه، پیش‌بینی هم‌زمان دو حوزه
├── 2_area_comparation.ipynb     # مدل بهبودیافته: LSTM دولایه + lag features + پیش‌بینی چندماهه
└── SARIMA_predictions.ipynb     # مدل جایگزین: SARIMA فصلی با grid search
```

## داده‌ها

ورودی اصلی یک فایل اکسل (`کامل.xlsx`) شامل ستون‌های زیر است:

| ستون | توضیح |
|---|---|
| `تاریخ` / `سال`, `ماه` | تاریخ ماهانه (برای ساخت ایندکس سری زمانی) |
| `High Temp`, `Low Temp`, `Avg Temp`, `Rainfall` | ویژگی‌های هواشناسی |
| `حوزه 1`, `حوزه2` | مقدار مصرف گاز در دو منطقه (متغیرهای هدف) |

> ⚠️ نام ستون هدف در فایل‌ها یکدست نیست (`حوزه2` بدون فاصله در برخی جاها، `حوزه 1`/`حوزه 2` با فاصله در جاهای دیگر). قبل از اجرا نام ستون‌های اکسل خودتان را با کد چک کنید.

## پایپ‌لاین پیش‌پردازش

1. **`match_dates.py`** — وقتی اکسل خام هواشناسی ستون‌های تکراری/تکه‌شده (مثل `دما.1`, `دما.2`) دارد، این اسکریپت آن‌ها را بر اساس نام پایه گروه‌بندی و روی هم می‌چیند (stack) و در `result_stacked.xlsx` ذخیره می‌کند.
2. **`weather.py`** — از ستون‌های عددی `سال` و `ماه` یک ستون تاریخ می‌سازد و با استفاده از کتابخانه `persiantools` معادل تاریخ شمسی را هم اضافه می‌کند.
3. در هر سه فایل مدل، مقادیر متنی/ناقص هواشناسی (`-`, `—`, رشته‌های آلوده) با تابع `clean_weather_value` با regex تمیز و به عدد تبدیل می‌شوند.

## مدل‌ها

### ۱. مدل پایه — `main_project.py`
- بررسی همبستگی بین ویژگی‌ها + تست ایستایی ADF
- نرمال‌سازی با `MinMaxScaler`
- دنباله‌های ورودی ۱۲ ماهه (`sequence_length=12`)
- معماری: `LSTM(50) → Dense(2)` برای پیش‌بینی هم‌زمان حوزه ۱ و ۲
- تقسیم train/test بدون شافل (75/25) به دلیل ماهیت سری زمانی
- پیش‌بینی ۶ ماه آینده با تابع `forecast` (بازخوردی/recursive)
- ارزیابی با MSE, RMSE, MAE, R²

### ۲. مدل بهبودیافته — `2_area_comparation.ipynb`
نسخه پیشرفته‌تر مدل پایه با چند بهبود کلیدی:
- ویژگی‌های چرخه‌ای ماه با `sin`/`cos` به‌جای عدد خام ماه
- ویژگی‌های **lag** (مقدار مصرف ۱، ۲ و ۳ ماه قبل) برای هر دو حوزه
- معماری عمیق‌تر: `LSTM(256, return_sequences=True) → Dropout → LSTM(128) → Dropout → Dense(2)`
- طول دنباله ۱۸ ماه، آموزش با `EarlyStopping` و `ReduceLROnPlateau`
- تابع پیش‌بینی چندمرحله‌ای که برای ماه‌های آینده از میانگین اقلیمی ماهانه (climatology) برای ویژگی‌های هواشناسی و از پیش‌بینی‌های قبلی برای lagها استفاده می‌کند (پیش‌بینی ۶ ماه آینده)
- ارزیابی جداگانه برای هر حوزه (MAE, RMSE, R²) + نمودار scatter واقعی در مقابل پیش‌بینی

### ۳. مدل جایگزین — `SARIMA_predictions.ipynb`
- مدل‌سازی سری زمانی کلاسیک روی `حوزه 1` با `SARIMAX`
- Grid search روی مرتبه‌های `(p,d,q)` و `(P,D,Q,12)` بر اساس AIC
- بررسی ایستایی با تست ADF (روی سری خام، دیفرنس‌گرفته‌شده، و دیفرنس فصلی)
- تحلیل ACF/PACF برای انتخاب مرتبه‌ها
- ارزیابی روی تست‌ست (RMSE, MAE, MAPE) و پیش‌بینی ۱۲ ماه آینده با بازه اطمینان ۹۵٪
- ذخیره خروجی‌ها در فایل‌های CSV/Excel جداگانه (summary، پیش‌بینی تست، پیش‌بینی آینده)

## نحوه اجرا

1. فایل اکسل خام هواشناسی را در صورت نیاز با `match_dates.py` و `weather.py` پیش‌پردازش کنید.
2. مسیر فایل ورودی (`کامل.xlsx`) را در ابتدای هرکدام از فایل‌های مدل با مسیر محلی خودتان جایگزین کنید.
3. یکی از مدل‌ها را اجرا کنید:
   - `python main_project.py` برای مدل پایه
   - نوت‌بوک `2_area_comparation.ipynb` برای مدل بهبودیافته
   - نوت‌بوک `SARIMA_predictions.ipynb` برای مدل SARIMA
